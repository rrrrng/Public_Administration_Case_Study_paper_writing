# 机制图生成工作流

本参考文件用于把 `.md` 文章、段落或论文阶段性材料转化为可审查、可返修、可用于图像模型生成的学术机制图或路径图。该流程服务于 Phase 5“机制模型与理论提升”，不是装饰性配图流程。

## 触发条件

当用户要求“画机制图”“画路径图”“生成理论模型图”“根据文章生成图片”“参考范文和 jpg 画图”时，执行本流程。

若用户只提供文章或段落，先抽取机制链并输出草图。若用户同时提供范文 `.md` 与对应 `.jpg`，把范文用于结构功能迁移，把 jpg 用于视觉风格迁移。不要复制范文概念、节点名称或研究结论，除非用户目标文本本身也包含这些内容。

## 输入识别

先把用户材料分为四类：

1. `target-text`：需要被转化为机制图的文章、段落、论文草稿或 Phase 5 材料。
2. `reference-article`：用于学习图表在论文论证中承担何种功能的范文 `.md`。
3. `reference-image`：用于学习版式、线条、配色、层级、标签密度和学术排版的 jpg/png/webp 图像。
4. `user-constraints`：尺寸、横版/竖版、黑白/彩色、中文/英文标签、期刊风格、是否需要图题图注。

缺少 `reference-image` 时，使用 `templates/mechanism-models.md` 中的图型作为结构参考。缺少 `reference-article` 时，不推断范文论证功能，只基于目标文本和 CN 范文质量基准生成图。

## 两阶段输出

### 阶段一：草图确认

不得直接生成图片。先输出 `templates/mechanism-diagram-brief.md` 中的草图简报，至少包含：

- 目标文本摘要。
- 机制链条，写成“前置条件 → 触发事件 → 主体认知与策略 → 资源/技术/组织重组 → 互动过程 → 中间结果 → 最终结果 → 理论命题”。
- 图型选择：因果链、多主体互动、多维耦合、路径模型、框架归纳之一。
- 节点表：节点名称、含义、来源依据、图中位置。
- Mermaid 或 ASCII 草图。
- 从范例文章和参考图迁移的结构与风格规则。
- 需要用户确认或补充的关键点。

只有在用户明确确认草图后，才进入阶段二。

### 阶段二：图像生成

用户确认后，生成面向 GPT Image 的绘图 brief 和独立生图 API 请求体。生图 API 与 Codex API 分离处理，不复用 Codex 会话、Codex 模型配置或 Codex API endpoint。默认 POST 地址为：

```text
https://api.openai.com/v1/images/generations
```

模型名使用可配置项，不硬编码到业务流程。默认建议使用 OpenAI 官方当前 GPT Image 模型 `gpt-image-2`；若用户写作 `gpt-image2`，按 API 规范模型名 `gpt-image-2` 处理，除非用户环境明确提供其他自定义模型名。

绘图 brief 必须包含：

- 图的用途：学术论文机制图/路径图，不是海报、信息图或宣传图。
- 输出语言：默认中文标签，除非用户要求英文。
- 版式：横版优先，适合论文插图；复杂机制可用上下双层或左中右三段。
- 视觉风格：白底、细线条、克制配色、清晰箭头、节点层级明确、避免卡通、3D、照片质感和装饰性背景。
- 内容约束：只绘制草图确认过的节点和关系，不新增概念。
- 可编辑性：标签简短、留白足够、便于后期在论文中替换文字。

## 生图 API 调用约定

执行生图前先读取 `references/image-api-configuration.md` 和项目配置文件。配置读取优先级为：用户当前任务显式设置 → `config/image-generation.local.json` → 环境变量 → `config/image-generation.example.json`。

把图片生成视为独立 HTTP 请求：

- Endpoint：`POST https://api.openai.com/v1/images/generations`
- Auth：默认使用 `Authorization: Bearer <IMAGE_API_KEY>`，不要使用 Codex API key，除非用户明确说明两者相同。
- Content-Type：`application/json`
- Model：默认 `gpt-image-2`，允许用户覆盖。
- Prompt：使用已确认草图后的 `image-generation-prompt`。
- Size：默认横版论文插图使用 `1536x1024`；若服务不支持该尺寸，退回 `1024x1024` 或用户指定尺寸。
- Output：优先请求 `png`；若服务返回 URL，下载或交付 URL；若服务返回 base64，解码为图片文件。

推荐请求体：

```json
{
  "model": "gpt-image-2",
  "prompt": "<confirmed image-generation-prompt>",
  "size": "1536x1024",
  "n": 1
}
```

若所用服务的 OpenAI-compatible 接口支持额外字段，可按用户环境增加 `quality`、`style`、`response_format` 或 `background`，但不要在 skill 中假设这些字段必然可用。

## 机制抽取规则

从目标文本中抽取机制时，按以下顺序判断：

1. 找出研究对象与核心现象。
2. 找出经验反常、治理悖论或解释缺口。
3. 找出制度、资源、技术、组织、情境等前置条件。
4. 找出触发事件、政策压力或问题冲击。
5. 找出关键主体及其认知、目标、压力和行动策略。
6. 找出主体之间的互动过程、资源重组或协同/抵抗关系。
7. 找出中间结果，避免从原因直接跳到最终结果。
8. 找出治理绩效、效能偏离、制度后果或理论命题。

若目标文本没有支撑某一环节，标为“待补充”，不要自行补全为强节点。

## 图型选择

- 因果链：适合单一主线、过程解释清楚的机制解释型论文。
- 多主体互动：适合部门协同、府际关系、基层执行、多方博弈案例。
- 多维耦合：适合制度、技术、组织、资源等多维框架归纳。
- 路径模型：适合展示两条以上机制路径、正反效果或分化结果。
- 框架归纳：适合提出新概念、新框架或理论模型。

优先选择最能表达文章机制的图型，而不是最复杂的图型。若文本只支撑一条机制链，不要强行画成多路径模型。

## OpenAI 模型配置参考

优先查阅 OpenAI 官方文档再确定可用模型名：

- GPT Image 1.5 模型文档：`https://platform.openai.com/docs/models/gpt-image-1.5`
- Images API 参考：`https://platform.openai.com/docs/api-reference/images/overview`
- Image generation 指南：`https://platform.openai.com/docs/guides/image-generation`

若官方文档或用户环境与本文件示例不一致，以当前 API 环境为准，并把模型名作为配置项传入，不写死在机制图工作流中。当前文档中的 GPT Image 模型包括 `gpt-image-2`、`gpt-image-1.5`、`gpt-image-1` 和 `gpt-image-1-mini`。

## 范例迁移规则

从 `reference-article` 学习：

- 图在论文中的位置：研究设计、案例分析、机制提炼或理论贡献。
- 图承担的论证功能：解释因果链、归纳框架、展示主体关系或提出命题。
- 节点命名方式：概念化命名、行动策略命名、维度命名或结果命名。
- 图注写法：是否说明图中箭头、层级、反馈关系和边界条件。

从 `reference-image` 学习：

- 版式方向、层级分区、箭头方向、节点形状和留白。
- 字号层级、线条粗细、颜色数量和强调方式。
- 是否使用分组框、虚线、反馈箭头、双向箭头或路径编号。

只迁移结构功能和视觉规则，不迁移范例中的实质概念。

## 质量检查

出图前检查：

- 图中每个节点都能回到目标文本或已确认草图。
- 箭头表达的是因果、过程、互动或调节关系，而不是无意义连接。
- 机制链至少包含前置条件、主体行动、互动过程、中间结果和最终结果。
- 图题和图注能说明图的理论用途。
- 参考图只作为风格约束，没有被内容复制。

出图后检查：

- 中文文字是否清晰、无乱码、无错别字。
- 节点是否遗漏、错位或新增。
- 箭头方向是否与草图一致。
- 版面是否适合论文插图，避免过度装饰、过密或像商业信息图。
- 若图像模型文字渲染不稳定，输出“文字替换建议”：保留图形布局，建议用户后期用编辑软件替换标签。

## 返修策略

返修时只改一个主要维度：

- 内容返修：增删节点、调整关系或修正机制链。
- 版式返修：改横竖版、层级、分区或留白。
- 风格返修：改颜色、线条、字体感觉或学术克制程度。
- 可读性返修：缩短标签、减少节点、提高对比度。

每轮返修都保留上一版草图和修改理由，避免反复漂移。
