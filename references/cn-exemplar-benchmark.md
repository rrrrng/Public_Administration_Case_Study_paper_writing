# CN 范文质量基准

本基准从 `templates/CN/` 中《公共管理学报》风格中文范文归纳而来。用于生成或修改中文公共管理案例研究论文时，优先级高于一般写作建议。不要复制范文原句；只学习其问题组织、论证密度、章节功能和证据—理论转换方式。

## 1. 成稿目标

目标文本应像一篇可投稿的中文公共管理案例研究论文，而不是政策宣传、经验总结或案例故事。合格成稿必须同时做到：

- 以治理悖论、理论缺口或经验反常开篇，而不是以政策重要性泛泛开篇。
- 在摘要中同时交代研究对象、方法、核心发现、机制解释和理论贡献。
- 在正文中呈现“文献不足—案例进入—经验发现—机制模型—理论回扣”的闭环。
- 将案例材料转译为概念、机制、行动策略或分析框架，而不是堆叠事实。
- 保留制度约束、组织策略、技术条件、资源配置、主体互动和结果偏差之间的张力。

## 2. 范文体例谱系

开始写作前必须从下列谱系中选择一种主导体例，并说明最相近的 2–3 篇 `templates/CN/` 范文。

| 体例 | 范文参照 | 适用任务 | 标题节奏 |
|---|---|---|---|
| 概念建构型 | “融合型政府”“制度趋同”“整体治理观” | 需要命名新概念、新治理形态或新理论视角 | 文献回顾与问题提出 → 研究方法与案例描述 → 案例分析与研究发现 → 结论与讨论 |
| 机制解释型 | “数治幻觉”“数字化协同” | 解释治理效能悖论、政策执行偏差、技术—制度错配 | 问题提出 → 概念界定/文献回顾 → 研究设计 → 案例分析 → 生成机制 → 结论 |
| 行动策略型 | “以数增权”“开放试点” | 解释牵头部门、基层组织或地方政府如何在约束中行动 | 问题提出 → 文献述评与分析框架 → 研究方法 → 行动策略/过程追踪 → 讨论与结论 |
| 框架归纳型 | “TOE框架”“四力耦合”“公共性再生产” | 从案例归纳多维框架、耦合模型或实践路径 | 问题提出 → 理论基础 → 研究设计 → 案例呈现 → 框架提炼 → 结论启示 |

标题可以是 4–7 个一级标题，但必须覆盖：问题提出、文献/理论对话、研究设计、案例呈现、案例分析、机制/理论提升、结论讨论。不要机械固定标题数量。

### 标题树质量规则

标题树决定论文是否像期刊文章。拟定标题树时执行下列检查：

- 一级标题不得全部使用“案例介绍”“问题分析”“对策建议”等通用名词。
- 标题必须体现所选体例：概念建构型突出概念定义和维度，机制解释型突出生成机制和作用链条，行动策略型突出主体行动与过程追踪，框架归纳型突出维度耦合和模型提炼。
- 案例分析部分标题应体现分析维度、过程线索或主体策略，而不是按材料来源简单排列。
- 机制或理论提升部分标题应指向“生成机制”“作用逻辑”“理论模型”“理论命题”之一。
- 若标题树读起来像调研报告目录，返回范文抽取和体例锁定阶段重做。

## 3. 开篇质量标准

范文开篇通常用三段完成问题建构。引言不只是介绍主题，更应该构造问题：主题介绍回答“研究什么”，问题构造回答“为什么值得研究、已有解释为何不足、本文如何回答”。

1. 现实变化或治理任务：说明该案例为什么处在重要公共管理议题中。
2. 经验反常或实践张力：指出现有政策预期与实际运行之间的偏差、悖论或未解释现象。
3. 理论缺口与研究问题：说明既有研究解释了什么、仍不能解释什么，并提出明确研究问题。

开头背景句或第一组句子可按“宏观驱动力 → 机制解释 → 行为转化 → 现象落地”推进：先说明具体制度、技术、社会或组织变化，再说明这种变化如何重塑原有结构，继而说明主体行为、关系或处境如何转化，最后落到本文需要解释的现象。

避免以下开篇：

- 只写“具有重要意义”“亟待研究”，没有具体张力。
- 只罗列政策背景，缺少研究问题。
- 直接表扬地方经验，缺少反常、矛盾或机制追问。
- 只介绍主题，未把主题推进为可研究的问题。

### 问题链质量分级

低质量问题链通常表现为：

- 某政策很重要，因此值得研究。
- 某地做法很好，因此总结经验。
- 某领域研究较少，因此本文研究。

高质量问题链应至少包含一种可解释张力：

- 政策目标与执行结果之间存在偏差。
- 技术工具引入后反而产生组织摩擦、责任转移或效能偏离。
- 协同机制表面完善，但责任、资源、数据或激励配置错位。
- 既有理论能解释制度压力，却解释不了主体策略、过程转化或情境边界。

开篇不得只停留在“重要性”。将政策重要性转化为经验反常、治理悖论、解释缺口或机制追问后，再进入研究问题。

## 4. 摘要模板

中文摘要建议使用 5 句结构：

1. 研究背景与核心问题。
2. 案例与方法。
3. 主要表现或经验发现。
4. 生成机制、行动逻辑或理论框架。
5. 理论贡献与实践启示。

摘要必须出现具体核心概念或机制名，不要只写“提出对策建议”。关键词 3–5 个，应包含核心概念、治理场域和方法/机制词。

## 5. 文献回顾写法

文献回顾不是百科式综述，而是为研究问题搭建解释边界。每个文献段应按以下方式推进：

- 先概括一个研究传统或解释路径。
- 再说明该路径能解释的对象。
- 接着指出其面对本案例时的不足。
- 最后把不足转化为本文的分析入口。

文献回顾末尾必须形成研究问题或分析框架。不要只以“相关研究较少”作为缺口；更好的缺口包括：解释层级不足、忽视主体能动性、未处理制度—技术互构、缺少过程机制、缺少中国情境边界。

## 6. 研究设计最低配置

研究设计必须可审计，至少交代：

- 案例选择理由：典型性、极端性、启发性或理论相关性。
- 资料来源：政策文件、访谈、观察、新闻、统计数据、平台材料等。
- 资料规模：数量、时间范围、访谈对象类型、文件来源。
- 分析方法：案例研究、过程追踪、扎根理论、框架分析或文本编码。
- 编码/分析步骤：开放编码、轴心编码、选择性编码，或事件链重构。
- 可信度处理：三角互证、匿名化、反例处理、材料缺口说明。

不能虚构访谈、文件、统计数据或编码过程。材料不足时，明确标注“待补充材料”，并降低结论强度。

不得使用 AI 模拟访谈、模拟田野记录或模拟证据链充当案例材料。材料不足时，缩小研究问题、降低结论强度或标注 `[材料待补]`；访谈提纲可以设计，但不能把设想的问题和回答写成已发生的访谈。

## 7. 案例分析段落标准

每个案例分析段落应具备“判断—材料—解释—推进”的四段式内核：

1. 首句给出本段理论判断或经验发现。
2. 中间引入材料编号、访谈、文件、事件或统计事实。
3. 解释材料如何支持判断，而不是让材料自行说话。
4. 末句推进到下一机制、下一维度或小结。

高质量段落应体现至少一种分析动作：主体策略识别、资源重组说明、制度约束解释、技术条件解释、组织互动追踪、结果偏差辨析、边界条件限定。

### 段落细则

案例分析段落按下列细则自检：

- 首句必须是可争论判断，而不是“某地开展了某项工作”的事实陈述。
- 材料必须带材料编号、访谈编号或来源类型；没有来源的材料不得支撑强判断。
- 材料之后必须解释“为什么该材料能支撑本段判断”，不能让材料自行说话。
- 段尾必须完成机制推进、边界限定、反例处理或转入下一分析维度。
- 每 3 个案例分析段落中，至少 1 个段落处理张力、反例、替代解释或限制条件。

若段落只呈现工作过程、政策成效或材料摘录，返回 Phase 4 重写为“判断—材料—解释—推进”。

## 8. 机制模型要求

机制不是“因素列表”。机制必须写成可追踪链条：

`制度情境/政策压力 → 触发事件 → 主体认知与策略 → 资源/技术/组织重组 → 互动过程 → 中间结果 → 治理绩效或偏差 → 理论命题`

机制图、理论命题或分析框架至少出现一种。若提出新概念，必须说明：概念定义、构成维度、适用边界、与相近概念的区隔。

## 9. 理论贡献层级

理论贡献不能停留在“丰富了研究”。优先写成以下四类之一：

- 概念贡献：命名并界定过去研究未充分概念化的现象。
- 机制贡献：补充既有理论遗漏的过程链条。
- 边界贡献：说明既有理论在何种制度、技术或组织情境下成立或失效。
- 情境贡献：揭示中国治理场景中不同于一般理论预期的作用逻辑。

结论部分必须回扣文献缺口，说明本文如何改变、修正或限定既有解释。

## 10. 禁止清单

- 禁止把政策目标直接写成研究发现。
- 禁止用“成效显著、体系完善、持续推进”等宣传腔替代分析。
- 禁止正文出现内部工作标签，如“冲突触发”“材料碰撞”“机制判断”“理论落点”。
- 禁止无证据生成访谈、政策文件、统计数据和参考文献。
- 禁止使用 AI 模拟访谈、模拟田野记录或模拟证据链；材料不足时缩小范围、降低结论强度或标注 `[材料待补]`。
- 禁止只给对策建议而没有理论回扣。
- 禁止所有段落都以宏观口号开头，缺少案例材料和机制推进。
