# 《公共管理学报》案例研究论文投稿检查表

本检查表用于全文生成后的最终自检。以 `templates/CN/` 范文体例为准，执行“功能完整、标题弹性、证据可追溯”的质量标准。

## 1. 体例结构检查

- [ ] 已执行 `references/paper-project-decomposition.md` 并形成 `paper-project-brief`。
- [ ] 已锁定一种主交付物类型：现象型、差异型、机制型或框架型。
- [ ] 已完成可用材料确认，并判断当前题目为 `可做 / 降级后可做 / 暂不可做`。
- [ ] 已写出第一版结论句，且对象、条件和结论点清楚。
- [ ] 已产出或计划产出最小可用结果：核心判断、核心分析段、证据链表或机制草图。
- [ ] 已建立本篇范围边界和 next-paper backlog，未把所有扩展想法塞入正文。
- [ ] 已选择并说明 2–3 篇 `templates/CN/` 相近范文。
- [ ] 已使用 `templates/exemplar-extraction-template.md` 抽取范文标题树、摘要结构、问题链和案例分析段落模式。
- [ ] 已读取并执行 `references/cn-exemplar-benchmark.md` 的范文质量基准。
- [ ] 如写作或修改引言、问题提出、研究背景，已读取并执行 `references/introduction-writing-module.md`。
- [ ] 未使用 AI 生成的访谈、田野记录或证据链；所有访谈材料均能回溯到真实记录。
- [ ] 材料不足处已缩小范围、降低结论强度或标注 `[材料待补]`，未用虚构材料填空。
- [ ] 全文覆盖：问题提出、文献/理论对话、研究设计、案例呈现、案例分析、机制/理论提升、结论讨论。
- [ ] 标题数量符合所选范文体例，不机械固定为 6 节或 7 节。
- [ ] 引言不只介绍主题，已经把主题构造成可研究的问题。
- [ ] 开篇形成“现实变化/治理任务 → 结构重塑/主体变化 → 经验反常/治理悖论 → 文献缺口 → 研究问题 → 案例与方法”的问题链。
- [ ] 开头背景句具备“宏观驱动力 → 机制解释 → 行为转化 → 现象落地”的推进关系。
- [ ] 摘要同时交代研究对象、方法、发现、机制解释和理论贡献。
- [ ] 已按 `references/manuscript-length-control.md` 建立篇幅预算，完整正文目标为 15000-17000 字，除非用户另有要求。
- [ ] 案例呈现与案例分析分工清楚，前者交代背景，后者提出解释。
- [ ] 正文没有使用“冲突触发/材料碰撞/机制判断/理论落点”等内部标签。
- [ ] 机制模型、理论命题或分析框架与案例材料一一对应。

## 2. 证据链检查

- [ ] 已建立案例档案、材料清单、证据链矩阵。
- [ ] 每个核心发现至少有一条一手材料或两条互证材料支撑。
- [ ] 未使用 AI 生成的材料或证据链；所有材料均能回溯到真实来源。
- [ ] 访谈、文件、观察、统计材料编号一致，正文可回溯。
- [ ] 访谈、文件、观察等材料编号与来源说明一致，匿名化处理前后可对应。
- [ ] 替代解释、反例或边界条件已进入讨论。
- [ ] 敏感材料已匿名化，未泄露具体人员或单位身份。

## 2.1 篇幅控制检查

- [ ] 正文估算字数在 15000-17000 中文字之间，不含参考文献、附录和材料清单。
- [ ] 若低于 15000 字，已优先检查并补足案例分析、机制提升、替代解释或边界条件，而不是填充背景。
- [ ] 若高于 17000 字，已优先压缩政策背景、重复文献和重复结论，而不是压缩核心材料与机制分析。
- [ ] 已输出章节篇幅复核表，说明每节估算字数、超出或不足位置和调整建议。

## 3. 理论贡献检查

- [ ] 研究问题不是“介绍案例”，而是解释治理现象、悖论、策略或机制。
- [ ] 文献回顾明确指出已有理论的解释边界。
- [ ] 文献回顾不是百科式堆叠，而是形成“已有研究能解释什么/不能解释什么/本文如何进入”的转换。
- [ ] 核心概念、机制图或理论命题至少出现一种。
- [ ] 理论提升不是重复案例发现，而是说明本文改变、补充或限定了哪条解释链。
- [ ] 理论贡献已写成概念贡献、机制贡献、边界贡献或情境贡献之一。
- [ ] 结论中明确写出边界条件和未来研究方向。

## 3.1 论证句式检查

- [ ] 已按 `references/argumentation-discipline.md` 检索“不是……而是……”“并非……而是……”“不只是……更是……”“不仅……而且……”“只有……才……”等强逻辑句式。
- [ ] 每个辩证逻辑段落写作前均已回答：该段指向本文需要解决的什么问题、解决了预期结果中的哪一部分、删除后论证结构是否仍完整。
- [ ] 每个强逻辑句式均能回溯到材料编号、对比对象和推理关系。
- [ ] 未用强转折、强递进或强排他句式替代证据链、前后对比、主体差异或理论碰撞。
- [ ] 无法通过段落结构审计或材料审计的强逻辑句式已删除、合并、降级或改写为低强度分析句。

## 3.2 迭代返工检查

- [ ] 已根据 `references/iteration-rules.md` 检查是否需要返回前序阶段。
- [ ] 如发生返工，已使用 `templates/revision-note-template.md` 记录问题、返回阶段和修复动作。
- [ ] 文献弱、证据弱、分析弱、贡献弱等问题没有被语言润色掩盖。

## 4. 引文格式检查

- [ ] 所有文献真实可查，不能核实的标为 `[引文待核实]`。
- [ ] 中文文献、英文文献格式统一。
- [ ] 正文引用与参考文献一一对应。
- [ ] 不虚构作者、年份、题名、期刊、卷期页码。

## 5. 投稿前检查

- [ ] 中文摘要说明研究问题、方法、发现、贡献。
- [ ] 关键词 3–5 个，包含核心概念与研究场域。
- [ ] 图表标题、编号、来源完整。
- [ ] 匿名审稿版本删除作者可识别信息。
- [ ] 全文避免政策宣传腔、工作总结腔和案例表彰腔。
