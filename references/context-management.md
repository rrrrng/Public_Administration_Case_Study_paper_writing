# 上下文管理

本 skill 面对大量 CN/EN 范文、访谈材料和证据矩阵时，必须控制上下文规模。

## 1. 范文读取策略

- 先按题名和主题选择 2–3 篇最相近 CN 范文。
- 每篇只抽取标题、摘要、一级标题、研究设计、1–2 个案例分析段落和结论贡献。
- 不一次性读取整篇长范文。
- 使用 `references/exemplar-extraction.md` 和 `templates/exemplar-extraction-template.md` 记录抽取结果。

## 2. 材料分层

| 层级 | 内容 | 用途 |
|---|---|---|
| Case Dossier | 背景、时间线、主体、事件 | 保持案例连续性 |
| Material Inventory | 文件、访谈、观察、统计数据 | 管理来源和编号 |
| Evidence Matrix | 论点、材料、支撑方式、反例 | 控制论证强度 |
| Mechanism Notes | 因果链、概念、命题、边界 | 理论提升 |
| Draft Notes | 标题树、摘要、段落计划 | 正文生成 |

## 3. 长项目规则

- 每完成一个阶段，输出 5–8 条 Completion Summary。
- 进入下一阶段前，只携带上一阶段的摘要、矩阵和关键材料编号。
- 对真实材料使用独立编号，如 `I01`、`D01`、`O01`。

## 4. 成稿前压缩

生成正文前，压缩为四个表：范文匹配表、标题树、证据链矩阵、机制链条表。正文只依赖这四个表展开。
