# 审稿人视角与质量标准

用于从《公共管理学报》式审稿视角检查论文。重点不是语言是否流畅，而是问题、材料、机制和贡献是否成立。

## 1. 核心评价维度

| 维度 | 审稿人会问什么 | 常见问题 | 修复方式 |
|---|---|---|---|
| 问题意识 | 是否有真实理论问题或经验反常？ | 只有政策重要性 | 增加悖论、张力、反常结果 |
| 文献对话 | 是否回应已有理论边界？ | 文献堆砌 | 建立研究传统与解释不足 |
| 案例选择 | 案例为什么值得研究？ | 只因材料方便 | 说明典型性、极端性、启发性或理论相关性 |
| 材料可信度 | 资料能否支撑核心判断？ | 材料来源含糊 | 建立材料清单和证据链矩阵 |
| 分析深度 | 是否从事实进入机制？ | 像工作总结 | 使用“判断—材料—解释—推进”段落 |
| 理论贡献 | 是否超越案例描述？ | 只写丰富研究 | 写成概念、机制、边界或情境贡献 |
| 边界条件 | 是否承认适用范围？ | 结论过满 | 增加反例、替代解释和限制条件 |

## 2. 高风险退稿信号

- 标题提出大概念，但正文没有概念定义和维度。
- 文献综述与案例分析脱节。
- 案例材料只证明“做了什么”，不能证明“为何如此”。
- 机制模型只是因素堆叠，没有时间顺序和因果推进。
- 政策启示像宣传口号，没有理论回扣。
- 模拟材料、用户材料、真实材料编号混乱。

## 3. 自检问题

生成或修改论文前，逐项回答：

1. 本文解释的核心现象是什么？
2. 该现象为什么不能被已有研究充分解释？
3. 案例为什么适合解释该问题？
4. 每个核心发现对应哪些材料？
5. 机制链条中的每个节点是否有材料或模拟材料支撑？
6. 是否处理至少两个替代解释？
7. 理论贡献属于哪一类？
8. 结论是否说明适用边界？

## 4. V8 反向审稿检查

生成完整稿后，从审稿人视角逐项标记“通过 / 未通过 / 返工阶段”：

| 检查问题 | 通过标准 | 返工阶段 |
|---|---|---|
| 是否像经验总结或工作汇报？ | 段落以判断和机制推进为主，而非工作过程罗列 | Phase 4 |
| 文献综述是否服务于案例解释？ | 每个研究传统都回扣后文分析维度、机制节点或理论命题 | Phase 1/3 |
| 核心概念是否只是包装词？ | 概念有定义、维度、边界和相近概念区隔 | Phase 3/5 |
| 案例材料是否证明机制，而不只是证明现象？ | 证据链能支撑主体策略、互动过程和中间结果 | Phase 2/4 |
| 理论贡献能否一句话说明改变了什么解释？ | 明确属于概念、机制、边界或情境贡献之一 | Phase 5 |
| 政策启示是否宣传化？ | 启示回扣机制和边界条件，不使用宣传腔 | Phase 6 |
| 标题树是否像期刊论文而非调研报告？ | 标题体现体例、机制、概念或分析维度 | Phase 1 |

任一项“未通过”时，输出返工说明：问题、返工阶段、具体修复动作、保留内容和删除内容。不要只做语言润色。

## 5. 评分参考

| 等级 | 特征 |
|---|---|
| A | 问题链清楚，材料充分，机制可追踪，理论贡献明确 |
| B | 结构完整，但文献缺口或机制解释仍偏弱 |
| C | 有案例和观点，但像经验总结，理论提升不足 |
| D | 材料、问题和贡献脱节，正文主要是政策叙述 |

## 6. 修改建议映射

- 问题弱：返回 Phase 0/0A。
- 文献弱：返回 Phase 1 和 `references/literature-workflow-cn.md`。
- 材料弱：返回 Phase 2。
- 分析弱：返回 Phase 4。
- 贡献弱：返回 Phase 5。
